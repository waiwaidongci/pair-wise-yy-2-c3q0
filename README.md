# 赛鸽运输笼周转台（含血统档案登记站）

运行：

```bash
npm start        # http://localhost:3024
npm test         # 周转判定规则单元测试
```

## 业务规则

鸽车回来后笼子不再“擦一遍就继续装”。每只运输笼按以下状态周转：

```
可用 available ──装鸽──▶ 使用中 in_use ──卸出最后一只──▶ 待消毒 pending_disinfection
                                  │                          │
                                  └─换笼（源笼清空同此）      └─登记消毒：药液批号/起止时刻/操作人
                                                                   ├─ 接触不足 10 分钟        ─▶ 停用 stopped
                                                                   ├─ 操作人 == 当趟押运人    ─▶ 停用 stopped
                                                                   └─ 合格                    ─▶ 待复核 pending_review
                                                                                                     ├─ 次日复核合格 ─▶ 可用
                                                                                                     └─ 复核不合格   ─▶ 停用
```

硬性约束：

- **一鸽一笼位**：每只足环同一时刻只能待在一个笼位；重复装入直接拒绝，必须走“换笼”。
- **换笼留痕**：记录时间、经办人以及源/目标笼位；源笼卸空自动进入待消毒。
- **消毒登记**：药液批号、起止时刻、操作人缺一不可；接触时长不足十分钟，或消毒操作人与当趟押运人为同一人，笼位继续停用（停用笼可整改后重新消毒）。
- **次日复核**：复核日期必须严格晚于消毒当天；合格后笼位才恢复可用，才能再装鸽。
- **押运人按运输周期登记**：空笼首装必填；续装、换笼进空笼自动沿用；复核通过后周期重置。

页面支持：查待消毒笼、可用笼位、待复核/停用笼，办理装/换/卸/消毒/复核，以及按足环号查“每鸽履历”（当前笼位与全部周转流水）。

## 分层结构

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 周转判定 | `src/turnover.js` | 纯状态机：状态推导、消毒判定、次日复核判定，不碰存储 |
| 笼位档案 | `src/store.js` | 笼子/笼位占用/流水台账持久化，强制不变量并委托规则层判定 |
| 页面交互 | `public/index.html` | 看板、表单、履历查询，全部通过 HTTP API 调用 |
| HTTP 编排 | `server.js` | 路由与错误码，不含业务规则 |
| 血统档案 | `src/pigeons.js` | 原登记站功能（建档、血统、转让、成绩） |

数据保存在 `data/pigeons.json`（旧文件首次启动时自动补入笼子种子数据）。
